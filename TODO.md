# Bookstore

Приложение состоит (или будет состоять) из следующих проектов:

### Что сейчас в работе:

* **Bookstore.WebClient** — клиентская часть приложения. Отвечает за взаимодействие с пользователем, отображение веб-страниц и обработку пользовательских действий.

  WebClient работает независимо от базы данных и не имеет прямого доступа к ней. Для получения и изменения данных он отправляет HTTP-запросы в **Bookstore.Api** по HTTPS.

* **Bookstore.Api** — серверная часть приложения. Отвечает за обработку запросов от WebClient, выполнение основной логики приложения и работу с базой данных.

  Запросы обрабатываются через Controllers, после чего при необходимости передаются в Services и Repositories.

  Для работы с базой данных используется **Entity Framework Core** и `DbContext`.

  Общая схема взаимодействия:

  `WebClient → Controller → Service → Repository → Database`

### Авторизация:

Авторизация и работа с пользователями находятся внутри **Bookstore.Api** и не выделяются в отдельный сервис.

Bookstore.Api отвечает за:

* регистрацию пользователей;
* вход в систему;
* проверку пользователя;
* роли и права доступа;
* защиту отдельных API-запросов.

Отдельный сервис авторизации на данном этапе не требуется, так как проект небольшой и не содержит нескольких независимых API.

### Что надо добавить потом:

* **Bookstore.Notyfiler** — отдельный сервис уведомлений. Его задача — отправлять пользователям уведомления, например письма на электронную почту.

  Notyfiler не должен напрямую зависеть от Bookstore.Api. Для получения информации о событиях он будет использовать **RabbitMQ**.

  Например:

  `Bookstore.Api → RabbitMQ → Notyfiler → Email`

  Благодаря этому отправка уведомлений не блокирует основной запрос пользователя, а сам Notyfiler можно изменить или временно отключить без изменения основной логики Bookstore.Api.

* **Bookstore.Logger** — отдельный сервис для централизованного хранения логов из различных частей приложения.

  Logger будет получать необходимые сообщения через RabbitMQ и сохранять их в отдельном хранилище.

  При этом Bookstore.Api не должен зависеть непосредственно от Logger.

### RabbitMQ:

RabbitMQ используется для асинхронного взаимодействия между основным приложением и дополнительными сервисами.

Bookstore.Api публикует события, которые могут обрабатывать независимые сервисы:

`Bookstore.Api → RabbitMQ → Notyfiler`

`　　　　　　　　　↘ Logger`

В дальнейшем к RabbitMQ можно будет добавить другие сервисы без необходимости изменять основную логику Bookstore.Api.

### SignalR:

В дальнейшем возможно использование **SignalR** для отдельных real-time сценариев.

SignalR не заменяет обычное взаимодействие WebClient с API, а используется только там, где пользователю необходимо получать изменения без ручного обновления страницы.

Например:

`Bookstore.Api → SignalR → WebClient`

для уведомления клиента об изменении состояния или появлении новых данных.
